# DOB preservation and reviewed listing links

This is a local implementation and is not a production release. The Amir Khan listing link and the one-year approximate-DOB policy were supplied under review reference `CLEAR01`, reviewer Greg Burden-Lowe. A source value `circa YYYY` or `approximately YYYY` is compatible with submitted birth years within one year on either side. Other approximate formats and unparseable dates remain unknown. Validate source evidence and release conditions before production use.

UN, UK, EU and OFAC parsers now retain multiple DOB alternatives in the existing semicolon-delimited field. Unsupported values are retained as non-comparable evidence, rather than discarded or promoted to an exact date. Existing source snapshots cannot recover DOBs or approximation markers already lost. A coordinated source refresh is necessary before these changes can be used safely; verify the original source values and both the PostgreSQL and Parquet publications. A missing or stale field is not evidence that no alternatives exist. Review imports and any source-specific unsupported formats before release.

`REVIEWED_LINKS` contains only manually approved groups. Each entry has `reviewed_by`, `review_reference` and a `records` mapping from source record ID to the exact `source_evidence_hash` from a freshly verified complete snapshot. Review must confirm identity using authoritative evidence, not names alone, and retain the decision in the referenced review record. The approved hashes must cover every group member, including a missing-DOB member. A changed source hash, missing member, duplicate member, overlapping group or different entity type disables the group. Registry changes alter the screening fingerprint. Do not publish unreviewed proposed links.

Only records independently retrieved and passing the name decision rules can participate: if any member is absent the group is not applied. This is conservative and can leave duplicate alerts; it does not suppress candidate retrieval or remove source listings. A complete approved group combines all known DOB alternatives. A matching or unknown alternative prevents DOB exclusion; an empty DOB on an otherwise linked record is not itself a contrary alternative. Every candidate retains its source and original DOB, plus group member IDs, DOBs, assessment and review provenance. Other approximate formats prevent automatic exclusion. The registry is code-owned and requires a coordinated release; there is no live review or link-management interface.

Before production use, obtain Compliance approval of the policy and each link, validate source completeness and precision, test positive and negative labelled cases, and release API and worker together. Verify the runtime source manifest and deployed version, then plan any historical rescreen separately. No current or historical alert is changed by editing the registry alone. Existing cleared reviews and prior runs require their own review and audit plan.
