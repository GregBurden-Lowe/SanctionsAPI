# Matching evaluation and release evidence

The matching pipeline has separate retrieval and assessment stages. PostgreSQL retrieves candidates by full-name and alias trigrams and, for an exact full DOB, by a matching whole-word name/alias and DOB. The Parquet backend scans eligible rows. Both use the same candidate evaluator. The PostgreSQL candidate cap fails closed; it is not a clearance. PostgreSQL normalizes aliases for retrieval using NFKD and ASCII folding, retaining raw comparisons and adding quoted nested-alias candidates. The shared evaluator parses the nested CSV and checks whole aliases rather than treating quoted semicolons as separators. This uses PostgreSQL Unicode normalization on a UTF-8 database; deployed compatibility and production-volume performance must be verified. Retrieval parity is not guaranteed for every spelling or transliteration.

The corroborated single-word rule is an operational heuristic, not a provider-designated weak-alias classification. Source-provided weak/strong alias metadata is not present in the existing flat source contract and must not be invented. A full DOB is supportive evidence, not proof of identity. Version `evidence-v8` prevents earlier cached results being reused, while existing run history is retained.

## Reproducible comparisons

Run `python scripts/evaluate_name_matchers.py tests/fixtures/matching_cases.json`. The fixed-threshold Jaro-Winkler comparison is a full-string-only baseline, not OFAC's complete algorithm or OpenSanctions' `logic-v2`. It has no retrieval, aliases, DOB, identifiers, source coverage, or organisation assessment. It is intentionally not wired into screening. The fixture is synthetic, constructed alongside the rules; it is a regression check rather than independent ground truth. The script outputs counts, disagreements and the corpus SHA-256. Do not commit sensitive operational cases or output. Threshold changes require separate, independent validation.

`tests/test_screening_policy.py` uses the same labelled synthetic policy cases for Parquet and a disposable PostgreSQL database, so it tests candidate retrieval as well as assessment. It also includes four public listed-name/alias examples drawn from historical OFAC notices for [Rivera-Luna](https://ofac.treasury.gov/recent-actions/20130605), [Khan](https://ofac.treasury.gov/recent-actions/20090112) and [Belan](https://ofac.treasury.gov/recent-actions/20161229). These examples test name retrieval against copied fixtures; they are not current-list verification or confirmed customer identities. Run the PostgreSQL cases with `SANCTIONS_TEST_ADMIN_DSN=postgresql:///postgres` only on an isolated local test server. Tests and replay can expose misses; they cannot prove equivalence across all names or watchlist releases.

## Acceptance before production

Freeze source version and hash, rules version, matching configuration, code version, backend and corpus. Have investigators independently label confirmed positives and difficult negatives, with expected source record IDs and any known names, aliases, DOBs and countries. Include repeat names, short names, sparse records, transliterations, spelling errors, false alerts, and records whose outcome changes under the proposed rules. Use `scripts/validate_acceptance.py` and `acceptance_metrics.py` for the reviewed operational pack. Measure expected candidate detection, false-alert rate, incomplete searches, retrieval misses, and review burden separately for sanctions and PEPs; review every missed confirmed positive. Do not treat previous false-positive dispositions or unreviewed clearances as ground truth.

Compare richer methods in a separate replay with a pinned algorithm and version. The published OFAC method combines whole-name and name-part comparisons using Jaro-Winkler and Soundex; OpenSanctions `logic-v2` includes culturally aware name comparison and identity features. Their scores and thresholds are not interchangeable with this application's score. Assess privacy, data licensing, source coverage, deployment and reproducibility before any integration; no external matcher is invoked by these changes.
